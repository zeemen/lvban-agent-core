01产品理念：从"导"到"伴"

这不是"AI 导游"的功能升级，而是产品范式的改变。传统旅游数字产品以景点为基本单位；AI旅伴以"这个人"为基本单位——当这个人带着孩子出行时，扩展为一个家庭。

导游式产品

景点 → 内容 → 导航 → 讲解。同一套讲解词面向所有人；每次打开都是陌生人；价值在行中、随行程结束而归零。会讲，但不懂你——而"会讲"正在被地图平台、OTA 和通用大模型迅速商品化。

旅伴式 agent

人 → 长期记忆 → 当前环境 → 意图 → 判断 → 服务 → 行动 → 新记忆。先认识谁在旅行，再判断他在哪里；每次打开都接着上次；价值跨越行前、行中、行后，随次数递增。

一个 agent 的六个属性

属性含义对应能力
有身份知道自己在陪谁旅行个人档案（身份层记忆），亲子模式下挂接家庭档案
有记忆知道一起去过哪、看过什么、问过什么、喜欢什么四层记忆 + 语义足迹
有环境意识知道你现在在哪、正在看什么、正在做什么Context Engine（位置 + 视觉 + 时间 + 活动）
有判断不是什么都讲，而是决定此刻该不该讲、讲什么、讲多深Explanation Planner
有主动性该提醒时提醒，该沉默时沉默Proactivity Engine
有连续关系一次旅程结束，是下一次的起点行后蒸馏 + 关系延续
产品首页不该先问"你准备去哪个景区"，而应逐步做到问"今天我们准备一起探索什么"。

02受众：潮汐、三层人群与一核三模

传统导览的六个问题

  • 讲解围绕地点组织，而不是围绕人；无法适应年龄、认知与兴趣的差异。
  • 单向播放，二十分钟就疲劳、失去兴趣。
  • 做攻略、找路线、管体力、答问题，全压在用户自己身上。
  • 游览结束即服务结束，兴趣、提问和经历没有沉淀。
  • 人工私家导游体验好，但价格高、供给少、质量不稳。
  • 通用 AI 能回答问题，却不知道你在哪、看过什么、接下来适合怎么走。

一个来自现场的观察：旅游的潮汐

节假日人群涌动，平日门可罗雀。K12 家庭在寒暑假出行是刚需，但假期之外几乎没有时间；平日的普通游客年龄偏大，尤其退休群体，对 AI 产品接受度低，市场教育成本高。能填平潮汐的，是那群有独立意识、时间相对自由、AI 接受度最高的人——独立出行的青年学生。他们在周末、春秋季和毕业季出行，Citywalk、特种兵旅行、打卡分享是日常；出行次数多、跨城市多、分享欲强，正是长期记忆和传播飞轮最需要的用户。

优先级人群出行节律产品模式付费与价值
主线独立出行的青年学生（约 16–24 岁，高中高年级至大学生）周末、春秋季、毕业季；填平平日潮汐同游模式：平等对话、随时接梗，像博学有趣的本地朋友客单价低、频次高；价值在记忆积累、UGC 与口碑
假期版K12 家庭（亲子研学）寒暑假、法定假期；波峰刚需亲子研学模式：对孩子是书童，对家长是管家家长付费意愿明确；研学包与会员
轻导览其他游客全年零散轻导览模式：不主动教育市场，但不拒绝顺带转化，不投入专项获客

一核三模

三类人群共用同一个 Agent Core、同一套 Top 30 锚点、同一套记忆系统，差异只在 Explanation Planner 的输出口吻与任务形态。模式由用户档案自动决定，也可以手动切换——同一个大学生，寒假带弟弟出来时切到亲子研学模式，记忆仍是他自己的。

主线

同游模式

不讲课、不布置打卡任务，而是边走边聊。看见一块残碑就能问"这上面刻的是什么"，走到乌衣巷能一起拆一首诗，吃饭时能聊秦淮河为什么是这座城市的商业中心。它记得你上个月在苏州聊过的园林，下次去北京会主动接上。分享的是一份有自己口吻的游记，不是一张打卡截图。

假期版

亲子研学模式

使用者是孩子，买单者是家长。对孩子：听得懂、能提问、像一场探索；对家长：少做攻略、不必自己答所有问题、能控制节奏与消费、知道孩子学到了什么，研学成果自然生成。行前领一个问题，行中围绕问题触发讲解与采集，行后把答案、足迹和孩子说的话织成研学记录。

轻导览

轻导览模式

按位置给简洁讲解，可问可不问，不推任务、不设人设、不做引导式对话。保留记忆入口但不主动经营；谁愿意多聊，agent 自然切到同游模式。

关于"青少年"的边界。16–18 岁仍是未成年人。年满 14 岁后不再适用儿童个人信息的特殊规则，但《未成年人网络保护条例》对不满 18 周岁用户的内容、消费与防沉迷要求依然适用；独立出行的高中生用户，其位置数据提示与消费限额要按未成年人标准设计。亲子模式下 14 岁以下孩子的数据由家长账户掌控。

03品牌与命名

五份企划在命名上得出同一个结论：保留"伴"字的理念，但把"伴游"移出主品牌。

为什么不叫"伴游"。在中文互联网语境和应用商店、小程序审核规则中，"伴游"已严重异化，与灰色陪游服务强关联；面向青少年和家庭的品牌尤其承受不起这种解释成本，名称本身也可能过不了审。它还会弱化"专业旅行服务"的信任感。
候选来源优点风险裁决
旅伴 / AI旅伴Kimi · ChatGPT温暖、陪伴感强，覆盖导游之外的长期关系；品类清晰词汇通用，需商标与重名检索采用为主品牌
游伴 / 行伴 / 旅搭子Gemini同行社交感，与青少年主线高度契合"搭子"口语化，不宜作正式品牌"搭子"保留为同游模式的人设称呼
随身向导 / AI旅行管家DeepSeek专业感与服务感强，信任度高偏工具，陪伴感弱保留为家长端称呼与轻导览模式的品类副标
知行少年 / 寻迹书童Gemini契合六朝古都与科举文化气场"知行"与公司现有道法产品线同名，会造成产品矩阵混淆不采用主品牌；"书童"保留为亲子模式孩子端人设
伴游原始提议最贴近 agent 的陪伴关系语义污染、审核风险、信任折损不作为任何对外名称

品牌结构

  • 品类：Personal Travel Agent / AI旅伴
  • 主品牌：旅伴
  • 首发产品名：旅伴 · 金陵同游（主线）；假期模式：旅伴 · 亲子研学（南京博物院 / 夫子庙实景探索版）

04产品定义与能力地图

旅伴不是"电子讲解器"，而是由四层服务构成、围绕一个生命周期循环运转的 AI 陪伴产品。四层服务在三种模式下都存在，只是形态不同。

服务层同游模式亲子研学模式轻导览模式
随身讲解按你的兴趣和上次聊过的内容讲；文字 / 语音 / 连续追问分龄讲解，观察—猜想—解释—追问按位置给简洁版，可追问
探索任务一个开放问题，边走边聊着解；无打卡、无评分找一找 · 猜一猜 · 说一说 · 亲子协作 · 时空连线不推任务
行程管家60 / 90 / 120 分钟路线；按停留、跳过、疲劳动态减量轻松游 / 深度研学 / 孩子主导三档；家长端静默提示基础路线与休息提醒
个人旅行记忆游记 + 语义足迹 + 偏好更新；跨城市延续研学手账 + 家长观察报告；孩子档案由家长掌控基础回顾；记忆入口保留

生命周期：行前 — 行中 — 行后 — 下次再见

探索问题是贯穿三段的第四条线：同游模式下是一个开放的话头，亲子模式下是一个研学问题；行前领，行中围绕它触发讲解与采集，行后把它织进游记。

第二次使用时的分水岭

一个大二学生，独自第二次来南京。agent 已经知道：他上次在南博对科举连续提问、对青铜器兴趣一般，走路快、不爱排队，上个月在苏州聊过园林的"借景"。这次进入江南贡院时，它不再播放"江南贡院始建于……"，而是说：

"你上次在南博问过古代人怎么考试，今天正好到了考场。先不讲历史——你猜这一排号舍里，当年最抢手的是靠近哪头的？"

同一件事放在亲子模式下，是对一个初一的孩子说"要不要沿着'古代南京学生的一天'走一遍"。两句话背后是同一套记忆，不同的是讲法。这种跨次理解，是旅伴与语音导览的分水岭。

05首发双 Demo 设计

两个场景不是两个产品，而是同一个 agent 在两种 Context Mode 下运行：共用用户档案、讲解、任务引擎、记忆与游后报告，只替换场景内容；同一个锚点由 Explanation Planner 输出同游版、孩子版与轻导览版三种讲法。

南京博物院（室内）夫子庙 · 秦淮风光带（室外）

同游模式：交互剧本示例

江南贡院 · 号舍"这格子比你宿舍床还窄，九天九夜吃住考都在里面。你刚才说期末周三天没出图书馆——放在明朝，这叫'入闱'。想不想知道当年落榜的人回家怎么跟爸妈交代？"

乌衣巷不先背诗，先问："你觉得这条巷子现在还住着'王谢'吗？"等用户看一眼招牌再接刘禹锡那两句，顺手聊一聊一千年里这条街换过几次主人。

文德桥"这桥有个'文德分月'的说法，农历十一月十五站在桥中间，月亮正好被桥分成两半。你算算那天你在哪？在的话我提醒你。"

南博 · 拍一下用户拍了错金银铜壶："你拍的角度正好——看壶肚上那些细到快看不见的金线。没有电焊的年代，你猜是先刻槽还是先铺金？"

记忆接续"你上个月在拙政园问过'借景'——秦淮河这一段两岸的马头墙，就是江南建筑把水当成庭院的另一种做法。"

亲子研学模式：交互剧本示例

任务唤醒进入历史馆，agent 不念展牌，而是发布任务："今天我们要在馆里抓出 3 只隐藏的古代神兽，第一只的线索就在你左前方的玻璃柜里！"

拍一拍孩子拍下错金银铜壶："蹲下来仔细看，壶肚子上是不是有很多像网格一样的金丝？你猜猜两千年前的工匠没有电焊，是怎么把金丝嵌进去的？"无论孩子怎么猜，先肯定观察力，再用听得懂的比喻讲清"错金银"。

实景互动踏入牌坊："欢迎来到明代的金陵城！今天你是一名进京赶考的江南才子，我是你的随身书童。"走到号舍前："你比划一下，这间小格子是不是还没你双臂展开长？如果是你，你会带哪三样东西进考场？"

家长端静默提示"已经连续参观 43 分钟，前方约 80 米有休息区，建议完成当前任务后休息。期间我可以给孩子讲一段故事，您喝杯茶歇口气。"

室内能力边界。普通手机 GPS 无法支持可靠的展厅级定位。MVP 采用"用户主动选展区 + 拍照辅助识别（结果允许纠正）+ 展品编号 + 已访问点位推断"的组合，不伪造精确位置，记录的是用户确认过的展区与展品。开发第一件事是在玻璃反光与人流遮挡下实测识别命中率：低于八成，就把行中交互从"拍一下"改成"问一句"为主，内容库的组织方式随之调整。

06核心引擎

行中是 agent 真正发生的地方。它要持续回答五个问题：我在哪、我在看什么、我在做什么、我现在需要什么、此刻该怎么服务——Context → Decision → Skill → Response / Action。

Context Engine：把一切输入压成一个"当前状态"

输入位置（GPS / 地图 / POI）、视觉（相机 / VLM）、时间、当前路线、是否在移动、正在聊什么、以前发生过什么、正在吃饭还是行走。输出一份当前上下文状态，交给决策引擎：

{
  "user": "u_2048",   "mode": "companion",   "party": "solo",
  "age_band": "18-24",   "location": "江南贡院",   "scene": "outdoor",
  "current_topic": "科举",   "interest": "high",   "fatigue": "medium",
  "time_left": 62,   "next_goal": "文德桥",
  "memory_hooks": ["苏州·拙政园·借景", "南博·科举·连续提问"]
}

亲子模式下多一个 family 字段：party 变为 "parent+child"，并挂接孩子档案的年级与讲解偏好；其余结构不变。

Proactivity Engine：决定什么时候开口

进入围栏 ≠ 必须开口。系统还要看：是否刚讲过、用户是否正在说话、是否在吃饭、是否高速移动、之前是否连续被忽略、是否正在做任务、本次触发的内容价值够不够高。

Explanation Planner：不是"找到答案"，而是"决定怎么讲"

agent 不把检索结果直接念出来。规划器输入当前展品、用户年龄段与模式、兴趣、已经听过什么、疲劳程度、本次探索问题、同行结构；输出是否讲、讲多长、用什么语言、先提问还是先讲、是否用故事、是否联系课本、是否关联过去记忆、是否留悬念、是否生成下一步。同一件文物，对不同的人有不同讲法。

Learning Engine：问题驱动的探索

研学不等于给景点加十道题；同游也不是把讲解词念得更口语。两者共用一个结构：大问题 → 观察 → 子问题 → 证据 → 对话 → 反思 → 结论。城市就是教材：秦淮河同时是历史、地理、语文、建筑和社会课题。知识结构因此不是单一景点库，而是 Place × Knowledge × Curriculum——同游模式用它接梗，亲子模式用它对齐课标。

07记忆系统

长期护城河不是 RAG，而是长期记忆。记忆的目的不是储存更多数据，而是让下一次服务比这一次更懂这个人。记忆的基本对象是个人；家庭是个人之上的一层关联——亲子模式下，家长账户挂接孩子档案，旅程记忆同时写入家长与孩子两个个人档案，并标记家庭关系。

User（个人档案，主键）
├── Identity / Preference / Journeys / Footprints
└── Family（可选扩展）
    ├── role: parent | child | sibling
    ├── members → 其他 User
    └── guardianship：14 岁以下成员的档案由监护人账户掌控

蒸馏规则

瞬时 → 旅程用户明确表达的状态和意愿即时写入；系统推断的只作为本次参考，不写入。
旅程 → 偏好行后一次性蒸馏：同类信号在本次出现 ≥ 2 次，或用户在行后回顾中确认，才升为偏好；首次出现只记"提过一次"。阈值待真实数据调优。
偏好 → 身份跨 ≥ 3 次旅程稳定成立，且与同行结构无关，才沉入身份层；身份层每一条都应可被本人（未成年人由监护人）看到并一键删除。
轨迹 → 足迹原始定位点只在旅程层保留，行程结束后 7 天内压缩；长期沉淀的是"语义足迹"。
个人 ↔ 家庭家庭旅程的记忆分别写入每个成员的个人档案并标记关系；孩子的偏好不自动合并进家长档案，家长的偏好也不代表孩子。孩子成年后可把档案从监护关系中解绑，记忆随人走。
不写入健康状况、财务、敏感身份属性，以及任何用户没说、是系统猜的"画像"。伴的前提是不被窥视。

采集原则：Usage Mode Collection

只有用户明确"开始今天的旅程"才进入 Journey Session；不做全天候或后台持续追踪。实时定位权限与长期轨迹保存分别说明、分别选择（"本次不保存轨迹 / 仅保存访问点位 / 保存完整轨迹"）。行程结束明确提醒并提供一键删除。室内不伪造精确位置。精确轨迹与可分享内容分离，分享内容默认不含轨迹、真实姓名与实时位置。

数据原则

Consent-first（明确授权后使用）· Purpose-limited（只为旅行与探索）· Memory-visible（能看到 agent 记住了什么，并解释"为什么这样推荐"）· Editable · Deletable · Exportable · No hidden profiling（系统推断不偷偷写入长期身份）· 未成年人扩展：16–18 岁用户的位置提示与消费限额按未成年人标准；14 岁以下由监护人账户掌控（Parent-controlled）。上线前单独完成法律法规与平台规则的合规评估，本企划不替代专项法律意见。

纯线上轻资产并不意味着没有资产。内容与数据就是资产——它要讲得比几百块请的野导游好，比官方语音导览有趣，而且不能编。

回答优先顺序：权威知识库 → 结构化图谱 → RAG 检索 → 现场展牌视觉读取 → 明确表达"不确定"并引导看现场说明或官方信息。年代、文物名称、尺寸、出土地点、人物关系、历史事件必须有据可查；区分确定事实、学术解释和传说故事；核心讲解经人工审校；建立错误反馈入口，问题内容可快速下线。

面向未成年人的交互原则

  • 不用排名和连续打卡制造焦虑；不用奖励诱导过度停留或消费。
  • 不随意收集语音、照片和人脸信息。
  • 亲子模式不鼓励孩子脱离家长单独行动；室外不要求边走边长时间盯屏。
  • 在道路、台阶和拥挤区域优先提示安全，而不是继续推送内容。
  • 轻量插画卡片 + 语音流（锁屏可听）+ 关键时刻唤醒相机，省电优先。

09技术架构与载体

一个 Agent，多个 Skill：不为每个景区重新造产品，也不为每类人群重新造 agent。原有的博物馆导览能力不需要推翻，而是下沉为 agent 的一个 Domain Skill。

技术原则

  • Model Router：不绑定单一模型。意图识别用低成本模型，普通问答用中型模型，深度解释规划用强推理模型，图像用 VLM，独立 Embedding，ASR + TTS 分离——控制 Quality × Latency × Cost。
  • Smartphone Native：只依赖手机的 GPS、相机、麦克风、耳机、地图与云端模型；不铺信标、不依赖场馆改造、不依赖官方二维码、不驻场。
  • 核心实体：User（主键）· Family（可选）· Trip · Journey · LocationEvent · POI · Exhibit · Question · Interaction · Preference · Memory · LearningTopic · KnowledgeNode · Task · Report · Ambassador · Merchant · Redemption。核心数据链：User → Journey → LocationEvent → Interaction → Distillation → Preference。
  • 新场景复制标准：每新增一个场景，只替换场景知识、点位路线、任务内容、服务规则和商户名单，不重新开发产品。

11GTM 体系：O2O 一体化

O2O 不是一条获客渠道，而是首发阶段的 GTM 骨架：线上占领出行决策时刻，线下把景区现场的人流变成扫码用户，再用到店兑换把线上行为拉回线下、把线下体验推回线上。校园大使同时是用户、推广者和内容创作者，这个三重身份是整个体系的中枢。轻资产的边界是"分销不自营"——服务点是合作方，不是员工。

线上到线下：内容 → 扫码；线下到线上：兑换 → 分享。校园大使在两端都在场，是这个环唯一不需要额外付费就能同时转动两边的角色。

12MVP 范围与验证

首发必须具备

微信授权与个人档案（家庭为扩展）；年龄段、模式选择与讲解偏好；夫子庙一条完整路线；南博一条精选路线；场景化讲解（同游版 / 孩子版 / 轻导览版三种口吻）与连续追问；探索问题与任务（亲子）；基础路线调整；游后游记 / 研学记录；个人长期记忆基础版；位置与轨迹授权管理；兑换码与商户核销；大使后台；内容纠错与安全反馈；运营后台（点位、知识、任务、路线、商户、版本管理）。

首发暂不做

全国景区覆盖；自研室内定位硬件；复杂 AR 实景游戏；社交排行榜与陌生人社区；自由行、酒店、门票等重交易；过多虚拟形象与养成系统；高压学习体系；自营线下团队。

七个核心假设

  1. H1 互动意愿用户愿不愿意一路和 agent 互动，而不是用完即走？
  2. H2 主动提问用户是否愿意主动问问题，而不只是听？
  3. H3 场景感知Context-aware 触发是否明显优于传统导览？
  4. H4 个性化解释按人讲的讲解是否明显优于统一讲解？
  5. H5 记忆价值长期记忆是否让第二次旅行体验明显提高？——邀请用户体验第二个场景，验证是否明确感到"它记得我上次喜欢什么"。
  6. H6 付费意愿青少年是否接受低价会员与文创兑换；家庭是否愿为研学包付费？
  7. H7 潮汐假设青少年主线是否真的填平了平日——平日用户中青少年占比是否显著高于假日？

最小验证闭环：用户进入场景 → 完成一次 agent 陪伴游览 → 生成旅行记忆 → 下一次感受到 agent 更懂自己。如果只有讲解和问答，没有游后记忆与再次使用价值，产品仍只是一个导览工具。

指标体系

北极星指标不是 DAU，而是 Meaningful Exploration Minutes：用户与 agent 共同完成的有效探索时长。旅游是低频产品，第二场景使用率和跨次记忆价值比日活更能说明问题；GTM 指标见第 11 节。

维度指标

用户价值满意度与推荐意愿（亲子模式按家长口径）；"比自己做攻略省心"认可比例；游记查看与保存率；主动修改或删除 AI 推断的比例
记忆偏好新增量；语义足迹完整度；跨次记忆被再次调用的比例；因记忆而提升的建议接受率
商业免费到付费转化率（按模式）；研学包付费完成率；会员转化率；商户核销与分佣额；单用户内容与模型成本；毛利与获客回收周期
长期90 / 180 天复游率；第二场景使用率；跨城市使用率；分享获客转化率

13路线图与团队

0–3 个月 · 场景与 GTM 验证产品原型与品牌基础；两个场景各一条路线打透，同游版口吻优先；场景知识库与后台内容管理；小程序 MVP 上线；首批大使与商户点签约；按第 11 节 90 天节奏跑通扫码 → 完成 → 兑换 → 分享的闭环。
3–6 个月 · 付费与假期验证上线同游会员与研学包；寒假切换亲子版口吻验证假期波峰；优化 AI 成本与响应速度；建立内容审校、投诉与下线流程；验证复购、推荐与分享；商户点扩至第二批。
6–12 个月 · 记忆与复制扩展南京其他文化场景（明孝陵、总统府、城墙、六朝博物馆），形成"南京城市 agent"；选第二座城市验证复制能力——先复制大使体系，再复制内容；推出跨场景兴趣线与年度旅行档案；标准化新场景接入流程；按留存评估独立 App。
12 个月后华东文化旅行（苏州、杭州、上海、扬州）→ 中国文化旅行 agent。不是一个一个做"景点 App"，而是持续扩展 Travel World Model、Skill Coverage 和大使网络。

15下一步：四份技术规格

本企划之后，应立即进入四份核心技术规格，而不是继续扩充宏观概念。

  1. 《Personal Memory System 技术规格 V1.0》User Schema（主键）、Family 扩展与监护关系、四层记忆、写入策略、检索、蒸馏、语义足迹、个人 ↔ 家庭记忆分权、用户查看 / 修改 / 删除 / 解绑。这是最先要拆的一份：位置轨迹怎样写入、什么能成为长期记忆、家庭与个人的记忆如何分权、第二次旅行怎样检索调用，直接决定这款产品是真 agent，还是披着 agent 外衣的智能导览。
  2. 《Location & Context Engine 技术规格 V1.0》GPS 采样、Geofence、POI、停留检测、室内上下文、视觉锚点、Context State（含 mode 与 party）、Journey 状态机。
  3. 《Companion & Learning Agent Policy V1.0》三种模式的人设与口吻、年龄分层、讲解颗粒度、苏格拉底式提问、问题链、同游 / 亲子 / 轻导览的触发阈值、什么时候说、什么时候不说。
  4. 《Nanjing Dual-Demo MVP PRD V1.0》南博 18 个锚点 + 夫子庙 12 个锚点 × 三种口吻，兑换码与大使后台，形成 30 个精调场景 × 统一 Agent Core × 一套 Memory System × 两种 Context Mode——第一个可以真正进入 AI Coding 和用户测试的版本。
