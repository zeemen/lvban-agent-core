01产品理念：从"导"到"伴"

这不是"AI 导游"的功能升级，而是产品范式的改变。传统旅游数字产品以景点为基本单位；AI旅伴以"这个人"为基本单位，亲子模式下再扩展为 Family Unit。

导游式产品

景点 → 内容 → 导航 → 讲解。同一套讲解词面向所有人；每次打开都是陌生人；价值在行中、随行程结束而归零。会讲，但不懂你——而"会讲"正在被地图平台、OTA 和通用大模型迅速商品化。

旅伴式 agent

个人 / Family Unit → 长期记忆 → 当前环境 → 意图 → 判断 → 服务 → 行动 → 新记忆。先认识谁在旅行，再判断他在哪里；每次打开都接着上次；价值跨越行前、行中、行后，随次数递增。

一个 agent 的六个属性

属性含义对应能力
有身份知道自己在陪谁旅行个人档案 / Family Unit（身份层记忆）
有记忆知道一起去过哪、看过什么、问过什么、喜欢什么四层记忆 + 语义足迹
有环境意识知道用户现在在哪、正在看什么、正在做什么Context Engine（位置 + 视觉 + 时间 + 活动）
有判断不是什么都讲，而是决定此刻该不该讲、讲什么、讲多深Explanation Planner
有主动性该提醒时提醒，该沉默时沉默Proactivity Engine
有连续关系一次旅程结束，是下一次的起点行后蒸馏 + 关系延续
产品首页不该先问"你准备去哪个景区"，而应逐步做到问"今天我们准备一起探索什么"。

02市场机会与目标用户

传统导览的六个问题

  • 讲解围绕地点组织，而不是围绕人；无法适应孩子的年龄和认知差异。
  • 单向播放，孩子二十分钟就视觉疲劳、失去兴趣。
  • 家长既要做攻略、找路线，又要答问题、管体力，组织成本极高。
  • 游览结束即服务结束，孩子的兴趣、提问和经历没有沉淀。
  • 人工研学导师体验好，但动辄数百至上千元/半天，供给少、质量不稳。
  • 通用 AI 能回答问题，却不知道你在哪、看过什么、接下来适合怎么走。

一个来自现场的观察：旅游是高度潮汐化的市场

节假日与寒暑假客流高度集中，热门景区“人满为患”；普通工作日却可能明显冷清。这意味着 AI旅伴不能只按“总游客量”判断市场，而要按时间可支配性 × AI接受度 × 出行频次 × 分享意愿重新切分用户。

优先级人群出行节律产品角色战略价值
首选青少年 / 青年学生：有独立意识、出行决策自主度较高、AI 服务接受度高周末、春秋季、毕业季、短途跨城；相对有能力填补工作日与非寒暑假时段同游搭子：像一个博学、有趣、懂梗的本地朋友频次高、跨城多、分享强；最适合验证长期记忆与跨场景复用
其次K12 家庭（亲子研学版）寒暑假和法定假期集中爆发，需求刚性对孩子是探索伙伴，对家长是研学助教 + 行程管家付费意愿清晰、客单价更高，是旺季核心收入层
再次其他游客全年零散，平日以年龄偏大的游客更常见轻导览：即开即用、少配置、少教育顺带转化；不承担高额市场教育成本
一核三模。三类人群不做三套产品，而是共用一个 Agent Core、同一套位置 / Context / Knowledge / Memory 底座，只由 Explanation Planner、任务系统和 UI 入口切换为：青少年同游模式（全年主线）、亲子研学模式（寒暑假增强）、轻导览模式（其他游客）。这样既顺应旅游潮汐，又避免三条研发线同时膨胀。
关于"青少年"的边界。16–18 岁仍是未成年人。年满 14 岁后不再适用儿童个人信息的特殊规则，但《未成年人网络保护条例》对不满 18 周岁用户的内容、消费与防沉迷要求依然适用；独立出行的高中生用户，其位置数据提示与消费限额要按未成年人标准设计。

青少年主线：一个懂你的旅行搭子

不讲课、不布置打卡任务，而是边走边聊：看见一块残碑就能问"这上面刻的是什么"，走到乌衣巷能一起拆一首诗，吃饭时能聊秦淮河为什么是这座城市的商业中心。它记得你上个月在苏州聊过的园林，下次去北京会主动接上。分享的是一份有自己口吻的游记，而不是一张打卡截图。

亲子版：两类用户，两套价值

对孩子

听得懂，不是成人讲解的简化版；可以提问、选择、挑战、表达；游览像一场探索，而不是另一堂课；每次旅行都留下自己的作品。

对家长

少做攻略，到现场就能开始；不必自己回答所有问题；能控制节奏、时间、消费和内容深度；知道孩子看了什么、学到了什么、对什么感兴趣；研学成果自然生成，不用游后补做。

03品牌与命名

五份企划在命名上得出同一个结论：保留"伴"字的理念，但把"伴游"移出主品牌。

为什么不叫"伴游"。在中文互联网语境和应用商店、小程序审核规则中，"伴游"已严重异化，与灰色陪游服务强关联；面向亲子家庭的品牌尤其承受不起这种解释成本，名称本身也可能过不了审。它还会弱化"专业旅行服务"的信任感。
候选来源优点风险裁决
旅伴 / AI旅伴Kimi · ChatGPT温暖、陪伴感强，覆盖导游之外的长期关系；品类清晰词汇通用，需商标与重名检索采用为主品牌
随身向导 / AI旅行管家DeepSeek专业感与服务感强，信任度高偏工具，陪伴感弱保留为品类副标或家长端称呼
游伴 / 行伴 / 同游Gemini同行社交感，适合年轻客群与亲子研学定位略偏备选
知行少年 / 寻迹书童Gemini契合六朝古都与科举文化气场"知行"与公司现有道法产品线同名，会造成产品矩阵混淆不采用主品牌；"书童"可作孩子端人设名
伴游原始提议最贴近 agent 的陪伴关系语义污染、审核风险、信任折损不作为任何对外名称

一个 agent，三副面孔

面对人设口吻与原则
青少年（主线）同游搭子 / 博学有趣的本地朋友平等、接梗、不讲课；先问你怎么看，再说它怎么来；记得你上次聊过什么

04产品定义与能力地图

旅伴不是"电子讲解器"，而是由四层服务构成、围绕一个生命周期循环运转的 AI 陪伴产品。

服务层做什么关键原则
AI 私人导游识别当前场景；按年龄、兴趣、可用时间生成讲解；文字 / 语音 / 连续追问；推荐下一站而非机械播放成人版、儿童版、亲子讨论版三种表达
AI 研学任务官找一找 · 猜一猜 · 选一选 · 说一说 · 亲子协作 · 时空连线追求观察、提问、表达、关联，不追求答题数量
AI 行程管家行前生成 60 / 90 / 120 分钟方案；轻松游 / 深度研学 / 孩子主导三种模式；按停留、跳过、提问、疲劳动态减量闭馆、限流、预约等易变信息不由 AI 凭空保证
家庭旅行记忆保存授权的轨迹、点位、任务与偏好；自动回顾；建立孩子兴趣标签；下次延续事实记录与 AI 推断分开，家庭可查看、修改、导出、删除

生命周期：行前 — 行中 — 行后 — 下次再见

研学任务是贯穿三段的第四条线：行前领一个问题，行中围绕问题触发讲解与采集，行后把答案、足迹和孩子说过的话织成研学记录。

第二次使用时的分水岭

家庭包含爸爸、妈妈和一个初一的孩子。agent 已经知道：孩子喜欢历史、不喜欢连续听长讲解、上次对青铜器兴趣一般、对科举制度连续提问、今天只有 90 分钟。进入江南贡院时，它不再播放"江南贡院始建于……"，而是说：

"你上次在南博问过古代人怎么考试。我们现在正好到了江南贡院，要不要沿着'古代南京学生的一天'走一遍？"

这句话体现的跨次理解，是旅伴与语音导览的分水岭。

05首发双 Demo 设计

两个场景不是两个产品，而是同一个 agent 在两种 Context Mode 下运行：共用用户档案、讲解、任务引擎、记忆与游后报告，只替换场景内容；同一个锚点由 Explanation Planner 输出同游版与孩子版两种讲法。

南京博物院（室内）夫子庙 · 秦淮风光带（室外）
场景主题"一件文物，怎样讲述古人的生活？""一条秦淮河，怎样连接读书、考试、商业与城市生活？"
研学大问题古代的工匠没有电焊，是怎么把金丝嵌进铜壶的？古代一个普通人怎样通过读书改变命运？
定位方式拍展品 / 展牌视觉识别 + 展厅级确认 + 平面图；不承诺精准室内导航高德 / 腾讯地图 API，核心节点 15–30 米电子围栏
讲解触发"拍一下 / 问一下"双入口进入围栏自动唤醒 + 屏幕预设"好奇心气泡"抗噪
动线形态展厅序列，分叉少，按年级裁出一条线街巷线性 + 散点；60 / 90 / 120 分钟三档
核心节点约 18 件核心展品（竹林七贤砖印壁画、错金银铜壶、金缕玉衣等）约 12 个文化地标（天下文枢、大成殿、江南贡院、明远楼、文德桥、乌衣巷等）
互动形式微观视觉寻宝 + 苏格拉底式提问 + 跨时空连线实景角色扮演（进京赶考的江南才子）+ 诗词闯关 + 飞花令
典型时长2–3 小时，中途需要一次休息提醒半天到一晚，吃饭是动线的一部分
最难的一点玻璃反光、人流遮挡下的识别命中率人多、信号漂移时的"该不该开口"
验证重点核心展品识别可靠；"拍一下"自然；讲解明显优于展牌；孩子产生真实连续问答围栏触发稳定；不过度打扰；空间与课内知识能连接；轨迹形成有效语义足迹

南京博物院：交互剧本示例

任务唤醒进入历史馆，agent 不念展牌，而是发布任务："今天我们要在馆里抓出 3 只隐藏的古代神兽，第一只的线索就在你左前方的玻璃柜里！"

拍一拍孩子拍下错金银铜壶，agent 识别后开启对话："你找到这件铜壶啦！蹲下来仔细看，壶肚子上是不是有很多像网格一样的金丝？你猜猜两千年前的工匠没有电焊，是怎么把金丝嵌进去的？"

知识降维无论孩子怎么猜，先肯定观察力，再用听得懂的比喻讲清"错金银"工艺。

微导航"看完这件壁画，往右手边走大约二十步，找一个全身穿满玉片、像古代钢铁侠一样的宝贝，找到后拍给我看！"——用寻宝指令替代冷冰冰的室内地图。

家长端静默提示"已经连续参观 43 分钟，前方约 80 米有休息区，建议完成当前任务后休息。期间我可以给孩子讲一段故事，您喝杯茶歇口气。"

夫子庙：交互剧本示例

身份代入踏入牌坊触发围栏："欢迎来到明代的金陵城！今天你是一名进京赶考的江南才子，我是你的随身书童。先去前面的天下第一考场'江南贡院'领号牌吧！"

实景互动走到号舍前："你比划一下，这间小格子的宽度是不是还没你双臂展开长？古代学子要在里面连考九天九夜。如果是你，你会带哪三样东西进考场？"

应景对诗走到乌衣巷或文德桥，结合眼前河景拆解刘禹锡的《乌衣巷》，把课本里的必背古诗与真实砖瓦打通。

双馆联动"上午我们在南京博物院看到的明代状元卷，字写得像印刷体一样工整；现在你眼前的江南贡院，就是当年他们写出那份考卷的地方！"

同一节点，青少年同游版的讲法

江南贡院 · 号舍"这格子比你宿舍床还窄，九天九夜吃住考都在里面。你刚才说期末周三天没出图书馆——放在明朝，这叫'入闱'。想不想知道当年落榜的人回家怎么跟爸妈交代？"

乌衣巷不先背诗，先问："你觉得这条巷子现在还住着'王谢'吗？"等用户看一眼招牌再接刘禹锡那两句，顺手聊聊一千年里这条街换过几次主人。

文德桥"这桥有个'文德分月'的说法，农历十一月十五站在桥中间，月亮正好被桥分成两半。你算算那天你在哪？在的话我提醒你。"

记忆接续"你上个月在拙政园问过'借景'——秦淮河这一段两岸的马头墙，就是江南建筑把水当成庭院的另一种做法。"

室内能力边界。普通手机 GPS 无法支持可靠的展厅级定位。MVP 采用"用户主动选展区 + 拍照辅助识别（结果允许纠正）+ 展品编号 + 已访问点位推断"的组合，不伪造精确位置，记录的是用户确认过的展区与展品。开发第一件事是在玻璃反光与人流遮挡下实测识别命中率：低于八成，就把行中交互从"拍一下"改成"问一句"为主，内容库的组织方式随之调整。

06核心引擎

行中是 agent 真正发生的地方。它要持续回答五个问题：我在哪、我在看什么、我在做什么、我现在需要什么、此刻该怎么服务——Context → Decision → Skill → Response / Action。

Context Engine：把一切输入压成一个"当前状态"

输入位置（GPS / 地图 / POI）、视觉（相机 / VLM）、时间、当前路线、是否在移动、正在聊什么、以前发生过什么、正在吃饭还是行走。输出一份当前上下文状态，交给决策引擎：

{
  "location": "江南贡院",   "scene": "outdoor",
  "family": "2 adults + 1 child",   "child_grade": "初一",
  "current_topic": "科举",   "interest": "high",
  "fatigue": "medium",   "time_left": 62,   "next_goal": "文德桥"
}

Proactivity Engine：决定什么时候开口

进入围栏 ≠ 必须开口。系统还要看：是否刚讲过、用户是否正在说话、是否在吃饭、是否高速移动、之前是否连续被忽略、孩子是否正在做任务、本次触发的内容价值够不够高。

Explanation Planner：不是"找到答案"，而是"决定怎么讲"

agent 不把检索结果直接念出来。规划器输入当前展品、孩子年龄与年级、兴趣、已经听过什么、疲劳程度、本次研学主题、家长需求；输出是否讲、讲多长、用什么语言、先提问还是先讲、是否用故事、是否联系教材、是否关联过去记忆、是否留悬念、是否生成下一任务。同一件文物，对不同孩子有不同讲法。

Learning Engine：问题驱动的探索

研学不等于给景点加十道题。结构是：大问题 → 观察 → 子问题 → 证据 → 对话 → 反思 → 结论。以夫子庙为例，"古代一个普通人怎样通过读书改变命运"沿着夫子庙 → 国学 → 江南贡院 → 号舍 → 科举 → 状元 → 社会流动展开。城市就是教材：秦淮河同时是历史（为什么南京长期重要）、地理（城市为什么沿河形成）、语文（诗人眼中的秦淮）、建筑（为什么沿水展开）和社会（商业为什么聚集）。知识结构因此不是单一景点库，而是 Place × Knowledge × Curriculum。

学段讲法抓手
小学低龄它像什么、怎么用、有什么故事神兽、寻宝、色彩、角色扮演
小学高龄谁制作、怎样制作、为什么这样设计原因、比较、时间线、任务
初中材料、技术、制度、贸易与文化交流历史背景、语文课文、社会影响、因果关系

07记忆系统

长期护城河不是 RAG，而是长期记忆。记忆的目的不是储存更多数据，而是让下一次服务比这一次更懂这个人。记忆的基本对象是一个人；亲子模式下扩展为 Family Unit，孩子的记忆由家长账户掌控。

蒸馏规则

瞬时 → 旅程用户明确表达的状态和意愿即时写入；系统推断的只作为本次参考，不写入。
旅程 → 偏好行后一次性蒸馏：同类信号在本次出现 ≥ 2 次，或用户在行后回顾中确认，才升为偏好；首次出现只记"提过一次"。阈值待真实数据调优。
偏好 → 身份跨 ≥ 3 次旅程稳定成立，且与同行结构无关，才沉入身份层；身份层每一条都应可被本人看到并一键删除；亲子模式下由监护人管理儿童数据。
轨迹 → 足迹原始定位点只在旅程层保留，行程结束后 7 天内压缩；长期沉淀的是"语义足迹"。
不写入健康状况、财务、敏感身份属性，以及任何用户没说、是系统猜的"画像"。未成年人数据按年龄与监护关系处理；亲子模式下儿童数据由监护人账户掌控，可整体导出、可一键删除——伴的前提是不被窥视。

采集原则：Usage Mode Collection

只有用户明确"开始今天的旅程"才进入 Journey Session；不做全天候或后台持续追踪。实时定位权限与长期轨迹保存分别说明、分别选择（"本次不保存轨迹 / 仅保存访问点位 / 保存完整轨迹"）。行程结束明确提醒并提供一键删除。室内不伪造精确位置。精确轨迹与可分享内容分离，分享内容默认不含轨迹、孩子真实姓名与实时位置。

儿童与家庭数据原则

Parent-controlled（儿童账户由家长管理）· Consent-first（明确授权后使用）· Purpose-limited（只为旅行与研学）· Memory-visible（能看到 agent 记住了什么，并解释"为什么这样推荐"）· Editable · Deletable · Exportable · No hidden profiling（系统推断不偷偷写入长期身份）。

未成年人合规。14 岁以下儿童的位置与行为数据，需监护人单独同意并适用单独的处理规则（《个人信息保护法》第 31 条、《儿童个人信息网络保护规定》）。定位采集的告知、足迹的导出与删除、家长账户的掌控权，要在 demo 阶段定下结构；上线前单独完成法律法规与平台规则的合规评估，本企划不替代专项法律意见。

Top 30 锚点的八个要素

每个锚点人工精调：开场悬念 → 观察引导 → 提问 → 解释（三个学段各一版比喻）→ 故事 → 课本连接 → 记忆连接 → 下一步动作。其余内容由 RAG 覆盖，保证核心体验百分之百稳健。

防幻觉：Evidence-first

回答优先顺序：权威知识库 → 结构化图谱 → RAG 检索 → 现场展牌视觉读取 → 明确表达"不确定"并引导看现场说明或官方信息。年代、文物名称、尺寸、出土地点、人物关系、历史事件必须有据可查；区分确定事实、学术解释和传说故事；核心讲解经人工审校；建立错误反馈入口，问题内容可快速下线。

儿童交互原则

  • 不用排名和连续打卡制造焦虑；不用奖励诱导过度停留或消费。
  • 不随意收集孩子的语音、照片和人脸信息。
  • 不鼓励孩子脱离家长单独行动；室外任务不要求边走边长时间盯屏。
  • 在道路、台阶和拥挤区域优先提示安全，而不是继续推送任务。
  • 轻量国风插画卡片 + 语音流（锁屏可听）+ 关键时刻唤醒相机，省电优先。

09技术架构与载体

一个 Agent，多个 Skill：不为每个景区重新造产品。原有的博物馆导览能力不需要推翻，而是下沉为 agent 的一个 Domain Skill。

技术原则

  • Model Router：不绑定单一模型。意图识别用低成本模型，普通问答用中型模型，深度解释规划用强推理模型，图像用 VLM，独立 Embedding，ASR + TTS 分离——控制 Quality × Latency × Cost。
  • Smartphone Native：只依赖手机的 GPS、相机、麦克风、耳机、地图与云端模型；不铺信标、不依赖场馆改造、不依赖官方二维码、不驻场。
  • 核心实体：User · FamilyUnit · ChildProfile · Trip · Journey · LocationEvent · POI · Exhibit · Question · Interaction · Preference · Memory · LearningTopic · KnowledgeNode · Task · Reward · Partner · Report。核心数据链：User / FamilyUnit → Journey → LocationEvent → Interaction → Distillation → Preference。
  • 新场景复制标准：每新增一个场景，只替换场景知识、点位路线、任务内容和服务规则，不重新开发产品。

12MVP 范围与验证

首发必须具备

微信授权与个人档案 / Family Unit；年龄段、同游 / 亲子 / 轻导览模式与讲解偏好；夫子庙一条完整主题路线；南博一条精选主题路线；场景化讲解（同游版 / 孩子版两种口吻）与连续追问；亲子任务与跳过机制；基础路线调整；游后旅行记忆卡；个人长期记忆基础版 + 亲子 Family Unit 扩展；位置与轨迹授权管理；内容纠错与安全反馈；运营后台（点位、知识、任务、路线、版本管理）。

首发暂不做

全国景区覆盖；自研室内定位硬件；复杂 AR 实景游戏；社交排行榜与陌生人社区；自由行、酒店、门票等重交易；过多虚拟形象与养成系统；以"孩子学了多久"为核心的高压学习体系。

六个核心假设

  1. H1 互动意愿用户（青少年与家庭）愿不愿意一路和 agent 互动？
  2. H2 主动提问孩子是否愿意主动问问题，而不只是听？
  3. H3 场景感知Context-aware 触发是否明显优于传统导览？
  4. H4 个性化解释按孩子讲的讲解是否明显优于统一讲解？
  5. H5 记忆价值长期记忆是否让第二次旅行体验明显提高？——邀请家庭体验第二个场景，验证他们是否明确感到"它记得我们上次喜欢什么"。
  6. H6 付费意愿青少年是否接受低价会员与文创兑换，家庭是否愿为研学包付费？

最小验证闭环：用户进入场景 → 完成一次 agent 陪伴游览 → 生成旅行记忆 → 下一次感受到 agent 更懂自己。亲子模式下，该闭环以 Family Unit 运行。如果只有讲解和问答，没有游后记忆与再次使用价值，产品仍只是一个导览工具。

指标体系

北极星指标不是 DAU，而是 Meaningful Exploration Minutes：用户与 agent 共同完成的有效探索时长。旅游是低频产品，第二场景使用率和跨次记忆价值比日活更能说明问题。

维度指标
场景体验路线启动完成率；完成率与主动缩短率；点位平均停留与跳过；孩子有效提问率；亲子任务参与率；中途退出原因；定位 / 识别纠错率

15下一步：四份技术规格

本企划之后，应立即进入四份核心技术规格，而不是继续扩充宏观概念。

  1. 《Personal / Family Memory System 技术规格 V1.0》User / FamilyUnit Schema、Child Profile、四层记忆、写入策略、检索、蒸馏、语义足迹、用户查看 / 修改 / 删除。这是最先要拆的一份：位置轨迹怎样写入、什么能成为长期记忆、家庭与孩子的记忆如何分权、第二次旅行怎样检索调用，直接决定这款产品是真 agent，还是披着 agent 外衣的智能导览。
  2. 《Location & Context Engine 技术规格 V1.0》GPS 采样、Geofence、POI、停留检测、室内上下文、视觉锚点、Context State、Journey 状态机。
  3. 《Parent-Child Learning Agent Policy V1.0》年龄分层、讲解颗粒度、苏格拉底式提问、问题链、学龄适配、家长 / 孩子双模式、什么时候说、什么时候不说。
  4. 《Nanjing Dual-Demo MVP PRD V1.0》南博 18 个锚点 + 夫子庙 12 个锚点，形成 30 个精调场景 × 统一 Agent Core × 一套 Memory System × 两种 Context Mode——第一个可以真正进入 AI Coding 和用户测试的版本。
