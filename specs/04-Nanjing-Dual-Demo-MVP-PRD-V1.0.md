## 3. 用户旅程

### 3.1 主线：同游模式（青少年，独自来南京）

```
行前
  扫码进入（大使码 / 商户码 / 内容链接）
  → 微信授权（仅 openid，不索取手机号）
  → 3 个问题建档：年龄段 / 这次想怎么逛 / 语音还是文字
  → 选场景：南博 or 夫子庙
  → 领一个探索问题
  → 【授权页】定位 + 轨迹保存三档（默认"仅保存访问点位"）
  → 点"开始今天的旅程"  ← Journey 进入 ACTIVE

行中（夫子庙）
  进入"天下文枢"围栏 → 主动性引擎判定 SPEAK
  → 开场（缓存音频，零延迟）→ 用户追问 → 实时生成
  → 走到江南贡院 → 命中 memory_hook（如有上次记录）→ 跨次连接
  → fatigue 升高 → 缩短讲解 + 建议休息
  → 前 3 个点位免费，第 4 个点位触发付费墙

行后
  点"结束旅程" → 回顾页（记录了什么 / 一键删除）
  → 生成游记（带自己口吻）
  → 分享长图 → 领兑换码 → 到店核销
  → 蒸馏：旅程 → 偏好
```

### 3.2 假期版：亲子研学模式

与主线共用全部引擎，差异在：`mode=family_study`、孩子端人设（书童）、家长端静默提示卡、任务形态（找一找/猜一猜/说一说/亲子协作/时空连线）、行后产出为研学记录 + 家长观察报告。

### 3.3 轻导览模式

按位置给简洁讲解，无人设、无任务、无主动经营。提问 ≥ 3 次时询问是否升级为同游模式（规格 03 §1.2）。

### 3.4 第二次使用（H5 的验证场景）

```
第二次打开 → 首页不是"你准备去哪个景区"，而是：
  "上次在南博你围着科举问了好几轮。今天去夫子庙？正好是当年的考场。"
                 ↑ 来自 memory_hooks，带证据可点开看"为什么这么说"
```

**这是整个 MVP 最该被验证的一屏。** 如果这一屏做不出效果，产品仍只是一个导览工具。

### 4.5 锚点八要素（企划书第 08 节）

每个锚点人工精调，**八个要素 × 三种口吻**：

```yaml
anchor_id: fzm_jiangnan_gongyuan_haoshe
name: 江南贡院 · 号舍
scene_id: fuzimiao
poi_id: fzm_jiangnan_gongyuan
is_top30: true

k1_sources:                      # 可信资料源，必填，支撑 must_cite 六类字段
  - {title: "...", publisher: "...", url: "...", fetched_at: "..."}
reviewed_by: ["内容负责人", "外部历史顾问"]
reviewed_at: "..."

elements:
  opening_hook:                  # ① 开场悬念
    companion: "这格子比你宿舍床还窄，九天九夜吃住考都在里面。"
    child:     "你比划一下，这间小格子是不是还没你双臂展开长？"
    light:     "这里是江南贡院的号舍，科举考试时考生在此答卷。"
  observation:                   # ② 观察引导
    companion: "看一下进深和高度，想想人怎么在里面睡觉。"
    child:     "数一数，一间号舍里有几块木板？"
    light: null
  question:                      # ③ 提问
    companion: "想不想知道当年落榜的人回家怎么跟爸妈交代？"
    child:     "如果是你，你会带哪三样东西进考场？"
    light: null
  explanation:                   # ④ 解释（三种口吻各一版）
    companion: "..."
    child:     "..."
    light:     "..."
  story: "..."                   # ⑤ 故事
  connection:                    # ⑥ 课本或当下连接
    curriculum: {stage: "初中语文", ref: "..."}   # 仅 12_15 使用
    present_day: "你刚才说期末周三天没出图书馆——放在明朝，这叫'入闱'。"
  memory_link:                   # ⑦ 记忆连接（模板，运行时填 hook）
    template: "你上次在{place}问过{topic}，今天正好到了{here}。"
  next_action:                   # ⑧ 下一步动作
    suggest: "fzm_mingyuan_lou"
    reason: "监考与防弊，接着号舍讲最顺"
```

> 上表中的文案取自企划书第 05 节交互剧本示例，用于说明**结构**；史实表述须经 K1 核定与人工审校后方可上线。

## 6. 付费与解锁

| 层级 | 内容 | 价格 |
|---|---|---|
| 免费 | 每个场景前 3 个点位、少量 AI 问答、基础回顾；服务点扫码进入即免费 | — |
| 同游会员 | 全场景同游模式、拍照识物、游记生成、跨城市记忆、文创兑换资格、校园大使通道 | 低价月卡 / 学期卡；首发大使邀请免费 |
| 研学包 | 完整主题路线、全部分龄讲解与任务、游后研学报告与作文素材、一定期限回看 | 19.9–29.9 元 / 场 |
| 金陵通票 | 南博 + 夫子庙 + 后续扩展场景 | 68 元 / 季 |
| 年度会员 | 多城市权益、长期记忆与成长档案、更高问答额度、家庭多档案、年度旅行报告 | 待定 |

**解锁时机**（设计在付费意愿峰值）：

```
同游模式：  用户第一次"拍一下"得到一个意外有趣的回答之后
亲子模式：  孩子被寻宝任务吸引、主动拉着家长去找下一件文物时
```

实现为事件触发而非点位计数触发：监听 `first_photo_delight`（拍照 → 回答 → 用户追问）与 `child_pulls_parent`（任务进行中孩子连续交互 ≥ 3 轮）两个信号。

> 以上为价格实验起点，不是最终定价。未成年人消费限额按《未成年人网络保护条例》处理（16–18 岁同样适用）。

## 7. 游后产出

### 7.1 同游模式：游记

```
输入：journey 全量 interaction + semantic_footprint + exploration_question 链
输出：一篇带用户自己口吻的游记（不是模板填空）
     + 语义足迹时间线
     + 本次新增的偏好（展示给用户确认，确认后才升 L2 —— 规格 01 D2）
```

关键约束：**游记里出现的每一条史实，都来自已审校的锚点要素或 K1**，不由生成模型自由发挥。用户自己说过的话可以原样引用（这正是"像自己写的"的来源）。

### 7.2 亲子模式：研学记录 + 家长观察报告

```
孩子端：研学手账（探索问题的答案 + 走过的足迹 + 孩子说过的话 + 作文素材）
家长端：观察报告（孩子在哪些点位最投入、问了什么、学到了什么）
```

企划书第 08 节红线：不用排名和连续打卡制造焦虑——报告里不出现分数、等级、与其他孩子的比较。

### 7.3 分享长图

```
默认不含：精确轨迹、真实姓名、实时位置
默认包含：场景名、探索问题、2–3 个高光片段、兑换码（如有）
```

## 8. 兑换码与核销（F11）

```
完成路线 → 发放兑换码（一次旅程一码）
  code: 8 位，用户可读，绑定 journey_id + merchant_scope
  有效期：7 天
  到店 → 商户端核销 → 回写 redemption → 月度分佣结算（10%–20%，按核销不按曝光）
```

**中立性约束（硬性）**：

- 兑换品**只在行后环节**出现，不进入讲解、不影响路线推荐
- 商户信息不参与 Explanation Planner 的任何输入
- 南京博物院为公共文化机构，**馆内不做任何商业引导**，服务点只设在馆外与周边

这三条写进代码层面的隔离：`merchant` 相关数据不出现在 Context State，Planner 的输入契约（规格 03 §3.1）里没有商户字段——**结构上就调不到**。

## 9. 埋点与指标

### 9.1 北极星：Meaningful Exploration Minutes（MEM）

企划书定义为"用户与 agent 共同完成的有效探索时长"，本 PRD 给出可计算口径：

```
MEM = Σ over anchors of  min(dwell_sec_at_anchor, 600)
      where  该 anchor 上存在 ≥1 次 meaningful_interaction

meaningful_interaction =
      用户主动提问
   |  用户对 agent 提问作出回应（文字/语音/选项）
   |  用户完成一次任务步骤（亲子）
   |  用户拍照并接受或纠正了识别结果

不计入：移动中、吃饭中、IDLE 状态、仅播放未互动的时长
单点位上限 600s，避免一个点位刷满整次旅程
```

首发目标：**付费用户单次旅程 MEM ≥ 45 分钟**；免费用户 ≥ 12 分钟。

### 9.2 七个假设的验证口径

| 假设 | 指标 | 目标 | 规格 |
|---|---|---|---|
| H1 互动意愿 | 单点位平均交互轮次 | ≥ 2.5 | 03 |
| H2 主动提问 | 有效提问率 | ≥ 35% | 03 |
| H3 场景感知 | A/B：自动触发 vs 手动选择 | 交互轮次 +30% | 02 |
| H4 个性化解释 | A/B：按人讲 vs 统一讲 | 交互轮次 +30%，满意度 +0.5 | 03 |
| H5 记忆价值 | 跨次记忆调用率 ≥40%；记忆命中认可率 ≥60% | 见 01 §9.2 | 01 |
| H6 付费意愿 | 免费→付费转化率（分模式） | 同游 ≥3%；亲子 ≥12% | 本 PRD |
| H7 潮汐 | **平日用户中青少年占比 vs 假日** | 平日显著高于假日 | 本 PRD |

> **H7 是受众策略是否成立的直接证据**，也是最容易被忽略的埋点——必须从第一天就区分"平日/假日"与"用户年龄段"两个维度，否则 90 天后无法回答。

### 9.3 其余指标

```
场景体验：路线启动完成率 · 完成率与主动缩短率 · 点位平均停留与跳过
          · 有效提问率 · 任务参与率（亲子） · 中途退出原因 · 定位/识别纠错率
用户价值：满意度与推荐意愿（亲子按家长口径） · "比自己做攻略省心"认可比例
          · 游记查看与保存率 · 主动修改或删除 AI 推断的比例
记忆：    偏好新增量 · 语义足迹完整度 · 跨次记忆被再次调用的比例
商业：    免费→付费转化率（按模式） · 研学包付费完成率 · 会员转化率
          · 商户核销与分佣额 · 单用户内容与模型成本 · 毛利与获客回收周期
长期：    90/180 天复游率 · 第二场景使用率 · 跨城市使用率 · 分享获客转化率
GTM：     扫码量 · 扫码→完成路线率 · 完成→兑换率 · 兑换→分享率 · 分享→新用户转化率
```

## 10. 合规与审核

| 项 | 要求 |
|---|---|
| AI 生成内容标识 | 全局展示"AI 生成内容仅供参考"；符合深度合成服务标识要求 |
| 资质话术 | 明确"AI 服务，非持证导游"；**绝不出现"南京博物院官方""夫子庙指定"等字样** |
| 未成年人 | 16–18 岁位置提示与消费限额按未成年人标准；<14 岁由监护人账户掌控 |
| 个人信息 | 分项授权、最小采集、可删除、默认不公开；上线前完成专项合规评估 |
| 品牌 | 上线前完成：商标检索、小程序名称审核、旅游类目资质咨询、域名与同类产品重名检索 |
| 内容 | Top 30 核心讲解 100% 人工审校；纠错入口 + 单要素快速下线 |

## 11. 里程碑与验收

| 阶段 | 产出 | 验收门槛 |
|---|---|---|
| M0 规格冻结 | 四份规格评审通过 | 本文档 + 01/02/03 签署 |
| M1 内容定稿 | 30 锚点 × 8 要素 × 3 口吻，K1 来源齐全，双签审校 | 事实错误率 = 0 |
| M2 引擎打通 | Context Engine + Memory + Planner 端到端（无 UI，命令行/HTTP 可对话） | H1/H4 可在内部测出 |
| M3 小程序端到端 | 办公室模拟坐标与实拍照片走完全流程 | 全流程无阻断 |
| M4 **现场实测** | 南博 + 夫子庙现场 | **视觉识别命中率 ≥80%**（否则按 02 §4.3 熔断）；围栏逐点校准完成 |
| M5 提审上线 | 小程序过审 | — |
| M6 90 天验证 | H1–H7 数据齐全 | H5、H7 给出明确结论 |

> **M4 的识别命中率是一个真正的分叉点，不是一个要通过的检查项。** 低于八成，产品形态从"拍一下"改为"问一句"为主，首页主入口、引导文案、锚点内容的组织方式都要随之调整——这个分支的两套方案要在 M3 之前都准备好。
